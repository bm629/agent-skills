# b1 — third-party code-execution + isolation-model retrieval

**Trigger:** conditional — `business.platform.type in {app-store, dev-platform}`.
**Anchor (required-rooted):** `business.platform.type`. **Cap:** 8 — **ordering:** isolation
strength, then whether the model is documented normatively. **Sources:** `chrome-ext`,
`vscode-api`, `figma-plugins`. **Fallback:** `webextensions-cg`.

## Why this predicate is not a tautology

This survey RUNS only when `business.platform.type != "none"`, so that predicate — and any
paraphrase of "the project is a platform at all" — is true by construction here and gates nothing
This angle names **two of the seven** live enum values, so it genuinely
discriminates: a `marketplace`, a `social-network`, a `payments-network`, a `data-platform` and a
`media` platform all reach the survey with this angle correctly OFF.

**Falsifying witness:** `business.platform.type = marketplace` satisfies the type trigger and
leaves this angle false.

## Mechanism

Retrieve the isolation and permission model — the sandbox boundary, the capability grants, what a
complementor's code can reach in the host process. Only meaningful where third-party code actually
executes in-process, which is what the two enum values select for.

## Unique coverage

The security posture a complementor inherits. a1 records that an extension surface exists; this
records what it is allowed to touch.
