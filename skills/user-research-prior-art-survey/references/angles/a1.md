# a1 — open scholarly-index retrieval

**Trigger:** always. **Cap:** 60. **Sources:** `crossref`, `semantic-scholar`, `arxiv-listing`.
**Fallback:** `arxiv-listing`.

## Mechanism

Query the open bibliographic indexes by the map's `user-population` x `task` x `method`
vocabulary, filter to records whose full text is retrievable without a paywall, and follow the
citation graph one hop out from the highest-signal hits.

The three sources do different jobs and are not interchangeable. Crossref is the backbone: it
resolves DOIs and carries the metadata for almost everything published, but it does not rank by
relevance in a way this survey can lean on. Semantic Scholar supplies the citation graph — the
one-hop walk is the only mechanism here that finds work the vocabulary did not name. The arXiv
listing carries preprints, which is where recent interaction work appears first and where the
peer-review filter has not yet run.

## Query strategy

Build queries as an axis pair, not as a bag of terms. A `task` term alone retrieves the whole
field; a `population` term alone retrieves social science. The productive form is one task term
crossed with one method term, filtered by population where the population is nameable.

Record each query **verbatim as run**, including the field qualifiers and the date bound. For
the arXiv listing the query is the traversal: which subject listing, which pages, and the
criterion that selected from them.

## Following the resolver is part of this angle's mechanism

**The backbone index returns metadata only.** It gives you a DOI, a title and a venue — never a
method section. So the admission rule cannot be satisfied from a search result alone, and
following the DOI to the open-access full text is **the admission check**, not a cross-angle
excursion. Do it.

The resolved host — a publisher site, a repository, an institutional mirror — is not a registry
source and **takes no coverage cell**: the cell records the SEARCH, and the resolver-follow is
what turns a search result into an admissible candidate. Record where you landed in the
candidate's `admission.full_text_url`.

If the resolver leads somewhere paywalled, that is the abstract-only outcome: `unadmitted`, with
that reason. Do not bypass, and do not fall back to writing the record from the abstract.

**Three resolver outcomes, and only one of them is a paywall:**

| What happened | Outcome |
| --- | --- |
| Full text retrieved | Admissible, if it also states a method |
| Paywalled | `unadmitted`, `abstract-only` |
| The host refuses outright (403, bot block) | `unadmitted`, naming the refusal |

The third is not a paywall — you never saw the abstract either — and it is not an excluded
source. It happens on genuinely open-access articles whose publisher blocks automated clients.
Say what happened; the reason field is free text precisely so this has somewhere to go.

**An excluded fetch target does not make its literature inadmissible — and does not make it
admissible either.** A publisher excluded as a fetch target still owns real work, and a candidate
carrying its identifier is admissible **only where an open mirror is independently reachable**.
Where the resolver lands on the excluded host itself, that is an `unadmitted` outcome carrying
that reason — not a breach, and not something to route around. Be aware that this angle may not
be able to find such a mirror at all: the index links to the publisher, and the citation graph's
open-access pointer for a gold-open-access record can point straight back at the excluded host.
An on-scope record dying here is a real and recordable outcome, not a failure of the run.

## Attributing a query that spans two axes

The query strategy above crosses axes; the coverage grid has one cell per `(group, source)`. A
query built from a task term and a method term therefore has two candidate homes, and putting the
same result set in both makes `returned` and `kept` arbitrary — the grid reports the results
twice.

**Attribute each query to ONE cell: the group whose vocabulary bounds the result set.** In a
task×method cross, that is normally the task group — the method term narrows what comes back but
does not determine which literature was searched. Record the query verbatim in that cell, and
name the other axis inside the query string itself, which is where a reader reconstructing the
search will look for it. The other group's cells record their own queries; they do not inherit
this one's results.

## Unique coverage

Peer-reviewed, **method-bearing** findings — the only angle whose records state a population, a
method and a measured effect. That triple is what makes a finding weighable at all, and no other
angle in this registry reliably produces it.

## Failure modes

- **Retrieving on the method term alone.** "Usability evaluation" returns tens of thousands of
  records across every discipline that has ever borrowed the word. This is why `method` groups
  carry mandatory negative terms.
- **Admitting on an abstract.** An index result is metadata. Until the full text is open, the
  method section has not been seen, and a record built from an abstract is indistinguishable
  from one grounded in the method — which is this survey's core failure one layer along. Record
  it in `unadmitted` with `abstract-only` as the reason.
- **Reading a shared-pool throttle as an outage.** The citation-graph source runs a globally
  shared unauthenticated pool and says so; a 429 there is a normal operating condition. Record
  the cell as `rate-limited` with that cause, never as a searched zero.
- **Walking the citation graph more than one hop.** Two hops leaves the scope's vocabulary
  behind entirely and returns work about a different problem that happens to cite the same paper.

## The arXiv channel is a RECENCY WALK, not a search

The permitted paths are `/list`, `/abs`, `/pdf`, `/html` and `/archive`. **None of them is a
search endpoint** — the catch-all robots block disallows `/search` and `/api`. So the traversal
sees the recent submissions of a subject listing and nothing else, which for a scope whose
relevant literature is five to fifteen years old is close to useless as a discovery channel. Its
real value is currency: work that has not yet reached the peer-reviewed index.

Do not budget for it as though it were queryable, and do not record a zero from it as evidence
that a topic is unstudied — the channel could not have found older work in the first place. Say
so in the cell's `cause` or `selection`.

**Subject listings beyond the registry's example URL are in scope** where the scope's vocabulary
warrants them: a developer-tooling product is served by the software-engineering listing as much
as the human-computer-interaction one. Record which listings you walked, verbatim, as part of the
traversal.

## Fallback

`arxiv-listing`, key-less and independent of both indexes, so a gating change or an outage at
either cannot take this always-on angle down with it. A cell reaching it must record its
`selection`.

**It does not restore the citation-graph leg, and the registry says so.** The one-hop walk is
this angle's only mechanism for finding work the vocabulary did not name, and the listing has no
citation graph. When the graph source is unavailable, that capability is simply lost for the run
— record it as a coverage gap with its cause. Do **not** write `fallback_used: arxiv-listing` for
those cells: it would satisfy the fallback rule while claiming a substitution that did not and
could not happen, and the listing is already one of this angle's primary sources, so the cells
were owed regardless.

## Cap

60, and it is a budget rather than a corpus ceiling — Crossref is effectively unbounded for any
query this survey issues. It covers a domain x task x method grid at roughly a dozen records per
axis pair, plus the one-hop citation walk.
