# a1 — open scholarly-index retrieval

**Trigger:** always. **Cap:** 60. **Sources:** `crossref`, `semantic-scholar`, `arxiv-listing`.
**Fallback:** `arxiv-listing`.

## Mechanism

Query the open bibliographic indexes by the map's `user-population` x `task` x `method`
vocabulary, filter to records whose full text is retrievable without a paywall, and follow the
citation graph one hop out from the highest-signal hits.

The three sources do different jobs and are not interchangeable. Crossref is the backbone: it
resolves DOIs and carries the metadata for almost everything published, but it does not rank by
relevance in a way this survey can lean on. Semantic Scholar supplies the citation graph — the
one-hop walk is the only mechanism here that finds work the vocabulary did not name. The arXiv
listing carries preprints, which is where recent interaction work appears first and where the
peer-review filter has not yet run.

## Query strategy

Build queries as an axis pair, not as a bag of terms. A `task` term alone retrieves the whole
field; a `population` term alone retrieves social science. The productive form is one task term
crossed with one method term, filtered by population where the population is nameable.

Record each query **verbatim as run**, including the field qualifiers and the date bound. For
the arXiv listing the query is the traversal: which subject listing, which pages, and the
criterion that selected from them.

## Following the resolver is part of this angle's mechanism

**The backbone index returns metadata only.** It gives you a DOI, a title and a venue — never a
method section. So the admission rule cannot be satisfied from a search result alone, and
following the DOI to the open-access full text is **the admission check**, not a cross-angle
excursion. Do it.

The resolved host — a publisher site, a repository, an institutional mirror — is not a registry
source and **takes no coverage cell**: the cell records the SEARCH, and the resolver-follow is
what turns a search result into an admissible candidate. Record where you landed in the
candidate's `admission.full_text_url`.

If the resolver leads somewhere paywalled, that is the abstract-only outcome: `unadmitted`, with
that reason. Do not bypass, and do not fall back to writing the record from the abstract.

## Unique coverage

Peer-reviewed, **method-bearing** findings — the only angle whose records state a population, a
method and a measured effect. That triple is what makes a finding weighable at all, and no other
angle in this registry reliably produces it.

## Failure modes

- **Retrieving on the method term alone.** "Usability evaluation" returns tens of thousands of
  records across every discipline that has ever borrowed the word. This is why `method` groups
  carry mandatory negative terms.
- **Admitting on an abstract.** An index result is metadata. Until the full text is open, the
  method section has not been seen, and a record built from an abstract is indistinguishable
  from one grounded in the method — which is this survey's core failure one layer along. Record
  it in `unadmitted` with `abstract-only` as the reason.
- **Reading a shared-pool throttle as an outage.** The citation-graph source runs a globally
  shared unauthenticated pool and says so; a 429 there is a normal operating condition. Record
  the cell as `rate-limited` with that cause, never as a searched zero.
- **Walking the citation graph more than one hop.** Two hops leaves the scope's vocabulary
  behind entirely and returns work about a different problem that happens to cite the same paper.

## Fallback

`arxiv-listing`, key-less and independent of both indexes, so a gating change or an outage at
either cannot take this always-on angle down with it. It is narrower and carries a declared
15-second crawl delay, so the angle degrades to a real partial result rather than to nothing.
A cell reaching it must record its `selection`.

## Cap

60, and it is a budget rather than a corpus ceiling — Crossref is effectively unbounded for any
query this survey issues. It covers a domain x task x method grid at roughly a dozen records per
axis pair, plus the one-hop citation walk.
