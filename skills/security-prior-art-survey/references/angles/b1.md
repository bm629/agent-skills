# Angle b1 — ecosystem advisory lookup

**Precondition:** a named package or dependency set exists for the product. **This angle is
opportunistic**: early in a product's life there is no such set, and then it does not run and is
recorded as `not_run` with that cause — never as a zero-hit. "No package set was named" and "the
named packages have no advisories" are different facts, and only the second is a finding.

**Mechanism.** Exact-match query by package and version against an aggregating advisory
database. Not a search — a lookup, keyed on identifiers the product actually declares.

**Sources:** `osv`, `github-advisory`, `nvd`.

**Applicable group types:** `component`.

**Cap:** 40 advisories. **Ordering signal:** advisory severity, then recency.

## Query strategy

1. Take the named package set from the scope context — the packages, libraries and ecosystems
   the product declares. If the scope names none, stop: this is the `not_run` path.
2. For each package, query the aggregating database by package and version, or by commit where
   the dependency is pinned to one. Batch the queries; anonymous rate limits apply.
3. Record each advisory as a `registry` candidate under whichever identifier the database
   returns as primary. Where it carries aliases, note them in the relevance line — a database
   advisory id and a national-registry id for the same vulnerability are one item, and treating
   them as two is a dedup failure the synthesis wave inherits.
4. Consult the national registry **only to corroborate** what the aggregating database returned.

## Unique coverage

Exact package-and-version matching. Every other angle reasons about classes of weakness; this
one answers whether the specific version this product intends to adopt has a known advisory.
That is the sharpest coverage in the supply-chain family, which is precisely why its
non-firing must be recorded honestly rather than dressed as a clean result.

## Failure modes specific to this angle

- **Recording the not-run as a zero.** The single most damaging error available here. A product
  with no declared dependencies has not been shown to have safe ones.
- **Using the national registry as the primary.** Its enrichment policy narrowed sharply in
  2026: a large unenriched backlog moved to a not-scheduled state and ongoing enrichment was
  restricted to a prioritised subset, so a record can exist while its severity and
  affected-version metadata never arrive. Treat a record flagged modified-after-enrichment as
  incomplete, and never let its silence stand for absence.
- **Version-blind lookup.** An advisory against a version the product will not use is not a
  finding for this product; record the version you queried.

## Sanitization

The aggregating database and the platform advisory repository are fetched over the network and
their records embed third-party references and, sometimes, proof-of-concept links. Everything
retrieved passes through a **content-sanitization guardrail** before use, recorded per source.

## Fallbacks

Between the aggregating database and the platform advisory repository in either direction — they
publish the same schema and largely overlap. The national registry is corroboration, never a
fallback for either. If all are unreachable, that is an `unreachable` cell with the attempts
listed, not a quiet omission.
