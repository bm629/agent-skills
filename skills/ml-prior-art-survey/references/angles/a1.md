# Angle a1 — model-registry enumeration

- **Conditional:** none — always-on angle.
- **Searches these axes:** `ml-task`, `domain-term`.
- **Sources:** `huggingface-hub-api`, `huggingface-hub-pages`, `ngc-catalog`. **Fallback:** `ngc-catalog`.
- **Cap:** 40 — **ordering:** downloads within the pipeline_tag, then recency of the last commit.

## Mechanism

Query the Hub HTTP API by task tag and vocabulary. Resolve cards via the API with `?full=true` rather than fetching rendered pages: the Pages bucket is the tightest limit on that host, 100 per 5 min against the API's 500, so a card fetched as a page costs the same information at five times the budget. It is NOT the tightest bound in this registry — `ngc-catalog` at 30 s per agent request and `arxiv-listing` at 15 are both tighter, and this angle touches one.

## Why this cap

A BUDGET, not a bound — the Hub holds ~10^5 models and no cap makes this exhaustive. Ordering is downloads within the pipeline_tag; past ~40 the tail stops informing a rung decision.

## Why this fallback

A vendor-optimized catalogue survives when the community hub throttles, and its artifacts are the same models under a different distribution.

## What only this angle covers

The only angle that enumerates what EXISTS. Every other angle starts from a candidate this one
found, or from a document about one. It answers "what could we adopt at all", and its failure mode
is a corpus that looks empty because the vocabulary never reached it — which is why the wave-0
probe matters more to a1 than to anything else.

**Read the card through the API, not the page.** `?full=true` returns the card metadata without
spending a Pages fetch, and the Pages bucket is the tightest limit ON THIS HOST — 100 per 5 minutes
against the API's 500. The budget changes fivefold; the FORM of the evidence changes too, and this
angle is where that bites.

**`?full=true` returns fields, not prose — so quote a field.** The response carries `pipeline_tag`,
`tags`, `library_name`, `cardData` (`license`, `datasets`, `language`), `model-index` (the results
block, where a published metric lives), `downloads`, `likes`, `createdAt` and `lastModified`. It
carries **no README body and no prose field of any kind**. An `evidence_quote` here is therefore a
field value written `key: value` — `pipeline_tag: token-classification`,
`cardData.datasets: ["coastalcph/lex_glue"]` — and that is a full warrant, not a degraded one. Do
not fetch the rendered page to obtain a sentence: that spends five times the budget for evidence
no stronger than the field it was rendered from.

**`lastModified` is `source_claimed_modified_at`, never `as_of`.** It is the platform's claim about
the repo, delivered as an API field, so it is recorded with `source_claim_provenance: api-field`.
`as_of` stays `null` unless the content states when the FACT became true. Every model this angle
touches carries `lastModified`, so this is the ordinary case rather than the edge one.

**It is not the tightest limit in the registry, and your other two sources are tighter.**
`ngc-catalog` asks AI-agent user agents for 30 seconds between requests and `arxiv-listing` for 15.
Budget those at their own pace rather than at the Hub's.

**A download count is a popularity signal, not a quality one.** It is a legitimate ORDERING and
never an admission criterion — a model with few downloads and a card that matches the scope beats
a popular one that does not.
