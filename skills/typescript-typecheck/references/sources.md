## Primary (official) sources

- **TypeScript — TSConfig Reference** (`typescriptlang.org/tsconfig/`): the exact compiler-option names, what `strict` enables (the 8-flag family), and which flags are NOT enabled by `strict` (`noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, `noImplicitReturns`, `noUnusedLocals`, `noUnusedParameters`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`); `moduleResolution` values incl. `bundler`; `skipLibCheck`, `composite`, `incremental`, `noEmit`, `declaration` semantics and defaults.
- **TypeScript — Project References handbook** (`typescriptlang.org/docs/handbook/project-references.html`): `composite: true` forces `declaration: true` + all files in `include`/`files`; `references` array; `tsc -b`/`--build` builds dependencies in order and is incremental; `tsc -b` acts as `noEmitOnError`; worked example of one project referencing another.
- **TypeScript — Modules: Choosing Compiler Options** (`typescriptlang.org/docs/handbook/modules/guides/choosing-compiler-options.html`) and **moduleResolution** / **allowImportingTsExtensions** option pages: `moduleResolution: "bundler"` requires `module` `esnext`/`preserve`; `allowImportingTsExtensions` requires `noEmit`/`emitDeclarationOnly`; `module: "preserve"` implies `bundler` resolution.
- **TypeScript — `verbatimModuleSyntax`** option page + TS 5.0 release notes: preserves import/export per the `type` modifier, no elision; supersedes (deprecates) `importsNotUsedAsValues` + `preserveValueImports`; interplay with `isolatedModules`.
- **Vite — Features guide** (`vite.dev/guide/features`): "Vite only performs transpilation on `.ts` files and does NOT perform type checking", assumes the IDE + build process handle it, recommends running `tsc --noEmit` in the build script; esbuild "only performs transpilation without type information" (hence no `const enum`, no implicit type-only imports). Consistent across Vite v2–v4 + main.
- **vitejs/vite — create-vite `template-react-ts`** (`github.com/vitejs/vite`, `packages/create-vite/template-react-ts/`): the three-file split (solution `tsconfig.json` with `files: []` + `references` → `tsconfig.app.json` + `tsconfig.node.json`); `tsconfig.app.json` bundler block (`moduleResolution: "bundler"`, `verbatimModuleSyntax`, `moduleDetection: "force"`, `noEmit`, `jsx: "react-jsx"`, `erasableSyntaxOnly`, `noUnusedLocals/Parameters`, `noFallthroughCasesInSwitch`); package.json `"build": "tsc -b && vite build"`; the design discussion that `tsc -b` is type-check-only and `noEmit` lives in the config.
- **fi3ework/vite-plugin-checker** (`github.com/fi3ework/vite-plugin-checker`): runs TypeScript/vue-tsc/ESLint/Biome/Stylelint in worker threads, overlays errors in browser + terminal during dev; `checker({ typescript: true })`; positioned as a dev-time companion.
- **tsconfig/bases — `strictest.json`** (`github.com/tsconfig/bases`, `@tsconfig/strictest` on npm): the exact strictest base contents (`strict`, `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noPropertyAccessFromIndexSignature`, `noUnusedLocals`, `noUnusedParameters`, `allowUnusedLabels: false`, `allowUnreachableCode: false`, `checkJs`, `esModuleInterop`, `skipLibCheck`, `forceConsistentCasingInFileNames`); `extends` usage.
- **microsoft/typescript-go** (`github.com/microsoft/typescript-go`): native Go port, **preview / not production-ready** — "still a work in progress and is not yet at full feature parity with TypeScript"; npm `@typescript/native-preview`; `tsgo` command; core checking/declaration-emit/build-mode "done", watch a non-incremental prototype, language service in progress, API "not ready"; slated for TypeScript 7.0.
