# `a3`

Operational-canon retrieval. Walks the four governed first-party operational corpora for the documented practice a scaling decision is measured against.

## Wave-0 input

`failure-class`, `system-class`

Its input comes from **wave 0 and its own channel only**. An angle taking its input from a sibling
angle's OUTPUT would be reading a vocabulary the sibling minted, which L-9 forbids — and
`seed_input` is the anti-drift mechanism that makes the rule checkable.

## Applicable group types

`failure-class`, `system-class`

The owed grid crosses these groups with this angle's own sources INTERSECTED with the map's ACTIVE
set. All three terms: dropping any one is wrong in a measurable way.

Always. `trigger: always`, no `predicate`, and `trigger_anchor: []` — this type follows the five shipped validators that guard on truthiness and accept an empty anchor on an always-on angle.

## Cap and ordering

**`cap: 184`.** MEASURED 2026-09-04, not budgeted: the four governed corpora count 44 (SRE Book) + 30 (SRE Workbook) + 44 (Azure Cloud Design Patterns) + 66 (GCP Architecture Framework) = 184. **`ordering_signal`:** The source's own listing order, then the corpus's declaration order in `sources` above. Every one of the four is a walkable listing, so listing order is total here in a way recency is not — three of the four publish no per-page date.

Record `bound{cap, hit, ordering, dropped_note, ordering_deviation}`. The cap is transcribed
VERBATIM from the registry — an author does not widen their own cap. `hit: true` owes a
`dropped_note` a reader could RE-APPLY: name the ordering position reached and the first row that
fell off, never "the rest were dropped".

## Two REQUIRED sub-topics, recorded on the coverage grid

This angle carries coverage that has no computable trigger anywhere else. The capability map's
`infrastructure` cluster has **no required leaf**, and `data_residency`, `observability` and `dr`
are property-less objects — so no angle can be gated on deployment model or DR posture, which is
the single most load-bearing fact about how a system scales. Rather than ship an eighth
conditional angle that never fires, the coverage folds onto this always-on one.

| sub-topic | cell field | what it records |
| --- | --- | --- |
| Deployment | `deployment_model` | the deployment topology the walk found named — or `unknown` |
| Observability and DR | `observability_dr` | the observability and DR posture found named — or `unknown` |

**Record each on AT LEAST ONE cell of the grid, not on every cell.** The grid is closed exactly to
(group × source): a cell missing from that product is refused and so is a cell outside it, so a
sub-topic cannot be its own row. Record it on the cell whose walk found it.

**`unknown` satisfies the requirement.** The rule exists to make an absence VISIBLE, not to forbid
one — a scope that names no deployment model is a recorded fact, while a run that says nothing at
all is the gap this fold is closing. The gate refuses an `outcome: searched` a3 output that carries
neither field on any cell; a `not_run` output is untouched, because it carries no grid at all.
