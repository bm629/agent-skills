# `a1` — connector-catalog enumeration

## Mechanism

FILTER the connector catalogs by the map's own terms. Walks the five LIVE catalogs — nango-providers,
activepieces-pieces, n8n-nodes, pipedream-components, zapier-apps-sitemap — and records one
coverage cell per (group, catalog). `make-integrations-sitemap` is the sixth row it carries and is
DEAD: the map puts it in skipped[] and no cell is owed against it. Discovers from wave 0 only; it never reads another angle's
output.

**This angle takes its input from WAVE 0 or the capability map, never from another search child.**
It discovers from the vocabulary map's own groups and enriches from its own channel. The
cross-angle join happens at two places that are not angles — the coordinator's in-memory merge and
the extract child's deep read, both wave 2.

## Axes it searches

- **`category`** — the integration categories the product's capabilities imply
- **`capability`** — the product's own capability nouns that imply an integration
- **`domain-noun`** — the domain's own vocabulary for the systems it connects TO
- **`service`** — third-party services already named in the scope

## Cap and ordering

**Cap: `90`.** BUDGET — a filter over an unbounded corpus, so no number clears it. The five catalogs total
~5,800 enumerable entries (990 + 730 + 558 + 1,000 + ~2,500), but the RESULT size is a property
of the domain, not the corpus. Honesty is carried by the coverage cell and the stated ordering,
never by the number.

**Ordering: the catalog's own entry order, then the entry's own name ascending -- the two signals ALL FIVE catalogs expose. An earlier revision used category size descending as the tie-break, which only nango-providers can compute; a tie-break four of five sources cannot apply leaves the drop order undetermined wherever the cap binds.** Transcribe it VERBATIM into `bound.ordering`. Where the run
could not apply it, record the ordering it DID apply and say why in `ordering_deviation` — an
ordering nobody can re-apply is a cap with no honesty behind it.

## Precondition, in BOTH directions

**It holds when:** `always`.

**It cannot fail to hold.** This angle is ALWAYS-ON: there is no predicate to satisfy and no classification value that rules it out. A map recording `holds: false` for it is refused by `always-on-angle-holds`.

## What this angle uniquely covers

the service SET and the per-catalog MEMBERSHIP. `present_on[]` is this angle's alone, and it is
the one wave-1 observation wave 2 cannot recover: `found_by` is a single cell key, so a service
listed in three catalogs is ONE row and the other two memberships have no other home.

**Required sub-topic — integration CATEGORIES.** One coverage cell per `category` group. This coverage folds here because `integrations.categories` is property-less `additionalProperties: true` in the capability schema and cannot gate an angle of its own.

## No sibling dependency

This angle names no other angle's output anywhere above. Its mechanism reads the vocabulary map and
its own sources, so a survey missing any other angle still dispatches this one. Where a naive
reading of the taxonomy would have it consume `a1`'s candidates, the resolution is that it
DISCOVERS from wave 0 and ENRICHES from its own channel.

## Absent input

If every source above is unreachable, record each cell with its status and observable cause, set
`outcome: vacated` with the cause, and record NO candidates — recording one would mean a search
happened. If the angle was ruled out by the map, `outcome: not_run` with the map's verdict, and
nothing else.
